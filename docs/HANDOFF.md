# Fluxora: engineering handoff spec

Version 1.0 · design system foundation + screen specs for the Fluxora prototype (stock sync and order
recording for Beckycoo). Read alongside:

| File | What it is |
|---|---|
| `css/tokens.css` | **Source of truth.** Reference → semantic → component tokens as CSS custom properties. |
| `tokens.json` | Same tokens in W3C Design Tokens (DTCG) format, generated by `python3 tools/build-tokens.py`. Feed this to Style Dictionary / Tailwind / native. |
| `css/app.css` | Component and layout styles. Reads semantic/component tokens only; no raw colours. |
| `docs/design-system.html` | Living style guide. Every swatch and state renders from the real CSS. |

Stack today: vanilla HTML/CSS/JS, no build step, runs from `file://`. Everything below is framework-agnostic; React/Tailwind notes are at the end.

---

## 1. Principles that resolve ambiguous cases

1. **The stock number is the hero.** Only the size cell (woven-label treatment) is allowed to be visually loud. If a new element competes with it, quiet the new element.
2. **Colour means something.** Denim = action. Orange/green = Shopee/Tokopedia identity only. Red/amber/green = status only. Never reuse a status colour for a data series or vice versa.
3. **Never colour alone.** Every status carries an icon or text; Tokopedia always carries its diamond marker (tags) or hatch texture (charts) because the brand pair is only ΔE 7.9 apart for protan readers.
4. **Every press answers.** Pressed (1px down), busy (spinner + `aria-busy`), done (toast with the same verb as the button).
5. **Motion explains change.** Only `transform`, `opacity` and colour transitions. No layout animation. Self-running motion exists in exactly two places: the flux intro (once per session, skippable) and the login tag illustration.

## 2. Tokens

### 2.1 Architecture

| Tier | Prefix | Rule | Example |
|---|---|---|---|
| Reference | `--ref-*` | Raw palette and scales. **Never** referenced by components. | `--ref-denim-800: #24305a` |
| Semantic | `--color-*`, `--space-*`, `--radius-*`, `--font-*`, `--motion-*`, `--elevation-*`, `--layout-*`, `--z-*` | Purpose-mapped. What components read. | `--color-action-primary: var(--ref-denim-800)` |
| Component | `--button-*`, `--input-*`, `--panel-*`, `--table-*`, `--cell-*`, `--nav-*`, `--toast-*` | Only where one component needs its own knob. | `--button-height-md: 36px` |

Naming: `{category}-{property}-{variant}-{state}`, e.g. `color-action-primary-hover`.
Lint rule to add in CI: no hex/rgb literals and no `--ref-*` usage inside `app.css` or JS templates (exceptions: garment silhouettes in `ui.silhouette`, which depict product colours).

### 2.3 Typography

Family `font-family-base`: **Hanken Grotesk** 400/500/600/700/800, self-hosted WOFF2 in `fonts/` (OFL). `font-variant-numeric: tabular-nums` is set on `body`, so every number aligns; Hanken was chosen over Schibsted Grotesk because Schibsted widens commas/periods under `tnum` ("Rp59 , 6").

| Token | Size / line | Weight | Tracking | Usage |
|---|---|---|---|---|
| `display` | 44 / 46 | 800 | −0.03em | Login headline only |
| `heading` | 24 / 30 | 700 | −0.02em | Page title (h1 in top bar), login form title |
| `metric` | 28 / 32 | 700 | −0.02em | KPI values, "big" numbers |
| `title` | 20 / 26 | 700 | −0.02em | Drawer title |
| `title-sm` | 16 / 22 | 600 | 0 | Panel title (h2), size-cell number |
| `body` | 14 / 20 | 400 | 0 | Default text, table cells |
| `small` | 13 / 18 | 500 | 0 | Field labels, list bodies, toasts |

Rules: sentence case everywhere (no all-caps labels); max ~72ch for paragraphs; no monospace in the UI; never join meta with "·", use commas or separate lines.

### 2.5 Motion

| Token | Value | Usage |
|---|---|---|
| `motion-duration-instant` | 80ms | Press: `translateY(1px)` |
| `motion-duration-fast` | 120ms | Hover/focus colour, border |

|---|---|---|
| `sm` | < 640 | Search full width; simulator bar scrolls horizontally; demo-account scope text hidden |

## 3. Components

Each interactive component styles both the pseudo-class and an `.is-*` mirror (`.is-hover`, `.is-active`, `.is-focus`, `.is-disabled`, `.is-loading`, `.is-error`, `.is-selected`) so states can be rendered statically in docs and tests.

### 3.1 Button `.btn`

| Variant | Class | When |
|---|---|---|
| Primary | `.btn.primary` | The one main action of an area (Masuk, Serahkan kurir, Simpan barang masuk, Buat PO). Max one per panel/drawer footer. |
| Secondary | `.btn` | Other actions (Kemas, Batal, Laporkan selisih). |
| Ghost | `.btn.ghost` | Low-emphasis navigation inside panels (Buka forecast). |
| Danger | `.btn.danger` | Destructive (Batalkan pesanan, Reset data demo). Always behind an in-page confirm. |

Sizes: `.sm` 32px / `md` (default) 36px / `.lg` 44px. Modifier `.block` = full width.

| State | Primary | Secondary | Ghost | Danger |
|---|---|---|---|---|
| Default | bg `action-primary`, text `on-action` | bg `action-secondary`, border `border-default` | transparent, text `text-secondary` | text/border `action-danger` / `status-critical-border` |
| Hover | bg `action-primary-hover` | bg `action-secondary-hover`, border `border-strong` | bg `surface-sunken`, text `text-primary` | bg `status-critical-bg`, border `action-danger` |
| Active | bg `action-primary-active`, `translateY(1px)` | bg `action-secondary-active`, `translateY(1px)` | same as hover + 1px | same + 1px |
| Focus | `focus-ring` (keyboard only) | same | same | same |
| Disabled | opacity .45, `cursor:not-allowed`, `pointer-events:none`, `disabled` attr | same | same | same |
| Loading | label hidden (`color: transparent`), 16px spinner centred, `aria-busy="true"`, not clickable; width must not change | same (dark spinner) | same | same |

Content: verb + object, sentence case, ≤ 24 characters; no trailing arrows. The confirming toast reuses the verb ("Serahkan kurir" → toast "Diserahkan").

### 3.2 Text input `.field > span + input` (also `select`, `textarea`)

Anatomy: label (`small`/500/`text-secondary`) → control → hint (`caption`, `text-tertiary`) or error (`caption`, `status-critical`, icon).

| State | Spec |
|---|---|
| Default | h `input-height` 36 (`.field-lg` 44), border `border-strong`, bg `surface-raised`, radius `input-radius` |
| Hover | border `text-tertiary` |
| Focus | border `border-focus` + 3px halo `surface-selected` |
| Disabled | bg `surface-sunken`, text `text-disabled`, border `border-default` |
| Error | `.field.is-error`: border `status-critical` + 3px halo `status-critical-bg`; input gets `aria-invalid="true"`; message replaces hint |

Rules: never use the placeholder as the label; validation on submit, cleared on next input; errors say what is wrong and how to fix it, without apologising.

Variant: **size inputs** `.size-inputs` (4 columns S/M/L/XL, 44px, centred `title-sm`/600). **Opname input** `.cell .q-input` (60×44, `radius-xs`); takes warning/critical border when the current value is low/zero.

### 3.3 Size cell `.cell > .q` (signature)

Woven-label look: 60×44 box, `radius-xs`, inner dashed "stitch" inset 3px (`--cell-stitch`). Used **only** for stock quantities.

| State | Class | Spec |
|---|---|---|
| OK | `.cell` | bg `surface-hover`, stitch 14% opacity |
| Low (≤ `settings.lowStock`) | `.cell.lo` | bg/text `status-warning(-bg)`, stitch 50% |
| Out of stock | `.cell.zero` | bg/text `status-critical(-bg)`, stitch 60%, the word "habis" printed inside (9px) |
| In production | `+ .inc` | Chip under the cell, `status-info` on `status-info-bg`, "+n" = open PO quantity for that size |
| Just changed | `.flash` | 3px `color-accent` ring fading over `motion-duration-emphasis`, applied when the value differs from last render |
| Plain (non-stock numbers in a matrix) | `.cell.plain` | No box, no stitch |

Tooltip (`title`): "{model} {size}: stok {n}, {k} dalam perjalanan".

### 3.4 Tabs `.tabs` / Segmented `.seg`

Tabs switch datasets and show counts (`.n` pill; active pill is `action-primary`). Active = `text-primary` 600 + 2px bar `action-primary`. Segmented filters the same dataset: track `surface-sunken`, active item `surface-raised` + `elevation-1`. Both: hover → `text-primary`; keyboard focus ring.

### 3.5 Status, level, channel

| Component | Class | Rule |
|---|---|---|
| Level badge | `.lvl.{critical,serious,warning,good,info,neutral}` | 22px, `radius-xs`, `caption`/600, **always** with icon (stop/alert/ok/info) from `ui.lvl()` |
| Order status | `.st.{baru,dikemas,dikirim,selesai,batal}` | Distinct marker shape per status (ring, half, filled, square, strikethrough) |
| Channel tag | `.ch.{shopee,tokopedia,all}` | Name always written; Shopee = dot, Tokopedia = diamond |
| Deadline | `.deadline(.soon,.late)` | `soon` < 3h (warning), `late` < 0 (critical, "telat …") |

### 3.6 Navigation `.nav a`

40px, `radius-md`, icon 18 + label. Hover/active bg `surface-inverse-raised`; active adds a 3px `color-accent` marker on the left edge and `aria-current="page"`. Counter `.cnt` (pill; `.crit` = red when any order is overdue). Items shown depend on role (`FX.store.SCREENS`).

### 3.7 Panel, KPI strip, table, list

- **Panel** `.panel`: `surface-raised`, 1px `border-subtle`, `panel-radius` 12, `elevation-1`. Header 56px min with h2 + `.meta`.
- **KPI strip** `.kpis`: one surface, cells separated by 1px `border-subtle`. Never separate floating cards. Value `metric`; alert variant turns value `status-critical`.
- **Table** `.t`: header `caption`/600 on `surface-sunken`; cells 12px padding; numbers right-aligned; `tr.row-link` hover `surface-hover`; `.is-selected` `surface-selected` + `aria-selected`.
- **List** `.li`: badge · title/body · chevron; whole row clickable, `tabindex="0"`, Enter/Space opens.

### 3.8 Overlays and feedback

| Component | Spec |
|---|---|
| Drawer | Right side, `layout-drawer-width`, radius `xl` on the left corners, `elevation-3`, header/footer `surface-raised`, body `surface-canvas`. `role="dialog"`, `aria-modal="true"`. Focus moves to first field. Close: ×, Esc, scrim click. Enter: `translateX(32px)→0` + fade, `slow`/`enter`. |
| Confirm | Uses the drawer (browser `confirm()` is blocked in embedded viewers). Title = question, primary = the destructive verb. |
| Toast | Bottom-right, width `toast-width` 440, `surface-inverse`, `radius-md`, `elevation-2`. Title (`caption`/600, muted) + message. Max 3 stacked; auto-dismiss 4.2s; exit animation `base`/`exit`. Container `role="status"` `aria-live="polite"`. `.bad` variant (critical bg) only for blocked/failed actions. |
| Callout | `surface-sunken`, `radius-md`, `small`. `.critical` variant uses `role="alert"`. |
| Read-only bar | Info colours + eye icon. Shown at the top of any screen the role can view but not edit. |

### 3.9 Charts

- Daily revenue: stacked bars per day, Shopee bottom (solid), Tokopedia top (hatched pattern `#tkp-hatch`), 2px gap between segments, 3px rounded top, twin-date bars labelled ("11.11"). Legend shows share %. Hover: per-bar tooltip with both channels + units.
- Forecast: history = 2px `text-primary` line with 3px dots; forecast = 2px dashed `action-primary` line + ±1.2σ band at 8% opacity; dashed vertical "minggu ini" marker. Hover tooltip per point.
- Never a second y-axis. Gridlines `border-subtle`, axis text 11px `text-tertiary`.
- **Tooltip placement** (`bindTip` in `ui.js`): placed beside the hovered mark (right side, 10px gap), flips to the left when it would cross the chart's right edge, then clamped to `[0, chartWidth − tipWidth]`; top fixed at 8px. It must never rely on overflowing the panel, because `.panel` clips (`overflow: hidden`) for its rounded corners. Min width 168px. Tap toggles it on touch. Empty days read "Belum ada penjualan (hari ini)" instead of "Rp0".

## 3b. Logo and intro

### Logo

Three flux lines form an **F**: the two white lines sweep into the top arm, the yellow line branches into the middle arm. The meaning is the product itself: one stock bundle flowing into two channels.

| Item | Spec |
|---|---|
| Geometry | 64-unit box. Paths (single source `FX.MARK` in `js/intro.js`): `M16 52 V27 C16 17.5 22.5 11 32 11 H48`, `M22 52 V28 C22 21.5 26 17 32.5 17 H48`, `M28 52 V37 C28 32 31 29 36 29 H42`. Stroke 3.6, round caps. Tile radius 15. |
| Colours | On dark: lines `color-text-on-inverse`, branch `color-accent`, tile `color-surface-inverse-raised`. On light: lines `ref-denim-900`, branch `ref-thread-600`. Mono: `currentColor`. |
| Clear space | ≥ 8 units (the middle arm's height) on every side. |
| Minimum | Mark 16px (favicon uses stroke 4.4 for legibility); lockup 96px wide. |
| Don't | Rotate, add shadows, recolour the branch with a channel colour, detach the yellow line. |
| Files | `assets/logo/fluxora-mark.svg` (app icon), `-mark-light.svg`, `-mark-mono.svg`, `fluxora-lockup-dark.svg`, `fluxora-lockup-light.svg`. Wordmark is Hanken Grotesk 800, tracking −3%, converted to outlines (no font dependency). |
| In code | `FX.logo(size, { tile, line, branch })` returns inline SVG using tokens. |

### Intro animation (`js/intro.js`)

| Phase | Time | What happens |
|---|---|---|
| Flux field | 0 – 1.55s | ~700–1500 particles (scaled to screen area) stream along 3D magnetic-dipole field lines, `r = L·sin²θ`, rotated by azimuth φ; camera yaws 0.75 rad/s with a slight pitch; perspective `f = 700 / (700 + z)`; depth-based alpha; motion trails by painting the background at 22% each frame; additive blending. |
| Converge | 1.55 – ~2.9s | Each particle eases (cubic in-out, 0.75s) to its assigned point on the mark, staggered by its position along the stroke (bottom of the bundle first, then by line), so the F draws itself upward and the branch peels off last. Colour lerps from denim-300 to white / thread yellow. |
| Hand-off | 2.75s | Crisp SVG mark fades in at the exact particle positions (500ms); particles fade out over 600ms. |
| Wordmark | 2.95s | "fluxora" + tagline "Satu angka stok, semua kanal." rise 8px and fade in. |
| Exit | 4.3s | Overlay fades (`slow`, `exit`) and is removed; the welcome dialog (first sign-in) opens after it. |

Rules: plays once per browser session (`sessionStorage`), skippable by click, Esc, Enter, Space or the "Lewati intro" button (focused on open); never plays with `prefers-reduced-motion: reduce`; replay from Panduan → "Putar intro". Canvas only, no libraries; device-pixel-ratio capped at 2.

## 3d. Simulated arrivals on sign-in (`js/arrivals.js`)

Purpose: show the process moving during a demo. Every explicit sign-in (not a page reload with a remembered session) replays a batch of marketplace orders that "arrived" since the previous sign-in.

| Rule | Spec |
|---|---|
| Batch size | 3 on the first sign-in, then previous + 1 (60%) or + 2 (40%), capped at `settings.loginOrdersMax` (default 12, editable 3–40 in Pengaturan). Counter and last batch stored in `state.logins`. |
| Time window | Orders are backdated across the time since the previous sign-in, clamped to 90 min – 12 h, oldest first. `store.replay(ts, 'Marketplace', fn)` sets the write clock (creation time, movements, sales day) and the actor, and suppresses per-order re-renders; one commit at the end. |
| Order content | Channel 68% Shopee / 32% Tokopedia; product weighted by forecast demand; 18% two-item orders; 85% pick an in-stock size, 15% try any size, so sold-out sizes produce held checkouts (overselling prevented). Ship-by: instant couriers 2–3.5 h, others 10–30 h after creation, so some arrive close to or past the deadline. |
| Path | Every order goes through `store.placeOrder`, the same action a webhook calls: stock and both listings update, sync log rows are written, and reconciliation stays at 0. |
| Feedback | "Selamat datang kembali" drawer: three stats (new orders, Shopee/Tokopedia split, held checkouts), the window start time, a deadline callout (critical if any are already late), the latest 6 orders, and "Buka Pesanan". On an account's first sign-in the summary is embedded in the welcome drawer instead, so there is never more than one dialog. One activity row: "Sinkronisasi saat masuk: …". |
| Off switch | Pengaturan → "Pesanan contoh saat masuk" (Owner). Remove for production; real orders come from webhooks. |

## 4. Screens

### 4.1 Login (`body.is-auth`)

**Purpose.** Gate the app, pick the role. Demo accounts make all five roles reachable in one click.

**Layout.** 2 columns `1.05fr / minmax(420px, 1fr)`. Left: `surface-inverse` art panel (padding 40/48), logo top, illustration, headline (`display`, max 15ch) + lead (`title-sm`, `text-on-inverse-muted`, max 44ch) bottom. Right: canvas, form max-width 400, centred, gap `space-5`.

| Element | Spec |
|---|---|
| Email | `.field-lg`, `type=email`, `autocomplete=username`, placeholder `nama@beckycoo.id` |
| Password | `.field-lg`, `autocomplete=current-password`, inline "Lihat/Sembunyikan" toggle (`aria-pressed`, label swaps) |
| Remember | Checkbox, default on. On → `localStorage`; off → `sessionStorage`; storage blocked → memory only |
| Submit | `.btn.primary.lg.block` "Masuk". On submit: loading state ~450ms, then success or error |
| Error | `.auth-error` above fields, `role="alert"`, icon + message; offending field gets `.is-error` + `aria-invalid`, receives focus; form shakes once (4px, 320ms) |
| Demo accounts | 5 rows: avatar initials, name, email, scope. Click fills email + password and focuses "Masuk" (does not auto-submit, so the user sees what happened) |

## 5. Edge cases

| Case | Behaviour |
|---|---|
| Long product names / colours | Wrap within the model column; SKU stays on the colour line. Toast messages wrap; toast width fixed. |
| KPI value overflow | `nowrap` + ellipsis; abbreviated currency (`Rp59,6 jt`, `Rp1,25 M`). |
| Stock reaches 0 | Cell → `.zero`; both listings show 0; next checkout on either channel is held (critical toast "Overselling dicegah"). |
| Negative stock | Impossible by design: orders are validated before any write. |
| Photo missing | Drawn garment silhouette in the product colour; failed URLs are remembered so they are not refetched. |
| Storage unavailable | App runs with in-memory state; session lasts until reload. |
| Background re-render (live orders) | Preserves scroll position, focused input and caret. Drawers are not re-rendered. |
| Many notifications | Ringkasan shows 7; bell drawer shows all, sorted critical → serious → warning, then time. |
| Role without permission | Screen hidden from nav; direct URL falls back to the role's first screen; editable controls hidden, read-only bar shown. |

## 6. Accessibility checklist

- [x] Text ≥ 4.5:1, input borders/icons ≥ 3:1 (values in §2.2).
- [x] Visible `:focus-visible` ring on every interactive element; never removed without replacement.
- [x] Focus order follows visual order: sidebar → top bar (simulator, bell) → content → drawer (traps visually; Esc closes).

## 7. Implementation notes

- **Tailwind**: map `tokens.json` into `theme.extend` (colors from `color.*`, spacing from `space.*`, borderRadius from `radius.*`, boxShadow from `elevation.*`, transitionDuration/TimingFunction from `motion.*`). Keep semantic names (`bg-surface-raised`, `text-secondary`) rather than palette names.
- **React**: the `.is-*` state mirrors map naturally to props (`<Button variant="primary" size="sm" loading />`); render pseudo-states in Storybook with the mirror classes.
- **Fonts**: ship the five WOFF2 files; `font-display: swap`. If served over HTTP(S), add `<link rel="preload" as="font" crossorigin>` for 400 and 600 (omitted here because preload fails on `file://`).
- **Regenerating tokens**: edit `css/tokens.css` → `python3 tools/build-tokens.py` → commit both.
